# JKS Interactive 3.0.2 — corrective update

Base: the complete V3.0.1 package, including the participant redesign. This release specifically addresses the three follow-up requests. It does not claim to implement every proposed mockup pixel-for-pixel.

## Global presentation design
- Editor toolbar: **Presentation theme**, eight settings categories, live TV and phone previews.
- Shared TV/phone backgrounds and fallback colours; logos and position/size; separate heading/body fonts, sizes, colour and position; voting accent and card colour; default transition.
- New slides inherit supported design fields. Existing slides are not automatically linked or overwritten. Link property groups via **Use theme**, or explicitly choose to link all existing slides. Editing an inherited field creates a local override; other inherited fields continue to follow the theme. Join-slide vertical title position is retained when linking all to avoid QR overlap.
- Server resolves inherited fields for live displays and participants. Shared image data is stored once in the theme, rather than copied onto each linked slide. Import/export and duplication retain theme settings. Existing slide identifiers and scores are unchanged by migration.
- Voting appearance controls affect colours, not the rating scale or competition rules. Existing 60-second and 1–7 defaults are unchanged.

## Live controller
- Replaced old dropdown/Apply layout with a production console: dual TV previews, real heartbeat indicators, approximate recent participant count, current/next slide labels, three screen targets, sync control, clickable timeline, next/previous, blackout, private notes, live phone preview, contextual competition/interactive controls and private competition scores.
- Previous/Next respect the chosen screen target. Both TVs uses TV 1 as the reference when screens differ. Sync explicitly takes both to TV 1. Existing round confirmation, stale-state guards, vote preservation and server-side rules remain in place.
- Desktop layout is designed for a fixed-height viewport; individual panels may scroll, and narrow screens use a responsive scrolling layout. This layout has not been visually verified in a real browser.
- Display links open separate TV pages; press F in the TV browser to toggle fullscreen. A controller cannot force remote browsers into fullscreen. Presence is a heartbeat estimate, not a hardware status guarantee. Phone preview shows the shared live stage, not a specific guest's private vote.

## Visual slide type gallery
- Add and Change slide type open illustrated selectable cards for all ten types: Standard, Countdown, Multiple choice, Rating, Competition, Word cloud, Q&A, Results, Join session and Linked video.
- The card determines the created slide type and its corresponding configuration; selecting Change preserves the slide ID. New slides use the presentation theme. Existing interactive backend features are retained, not replaced with mockups.
- Poll/rating/word cloud/Q&A responses and publication require the respective live controls. Results slides publish competition rankings. Linked video remains experimental (direct HTTPS MP4/WebM, muted, browser-dependent synchronization).

This includes regression tests for legacy data, independent presentations/contests, navigation confirmation, 80 simulated concurrent votes, response validation, participant states, theme inheritance/overrides/relinking, compact persistence, duplication/import/export, all ten gallery cards and simulated creation/change-type actions. Therefore actual visual appearance, uploads and click/drag interactions in a deployed browser, responsive viewport fitting and physical TVs remain unverified. Run the existing browser test plus the manual checklist below in staging. The new theme save and gallery card selection require real UI validation; static/VM tests are not a replacement.

## Staging acceptance checklist
1. Export a design backup and keep a pre-upgrade Git commit. Use a staging Worker or rehearsal deck for test data; export real results separately if needed.
2. Existing Christmas design and scores unchanged after update. Open Presentation theme, set distinct TV/phone backgrounds, fonts, logos and voting colour. Create two slides: both inherit. Override one field on one slide, change theme again: only the overridden field stays independent. Reload, duplicate and export/import.
3. Open Add and Change slide type. Choose each card. Verify correct properties, TV/phone output and live controls; QR scans. Use a fresh test slide for each activity.
4. On a 1366×768 and 1440×900 browser, check both themes and production controller. Switch TV 1 alone, TV 2 alone, both, sync and next/previous. Verify confirmations during a running countdown and open voting. Confirm actual presence after devices connect and disconnect. Check phone preview and private notes.
5. Rehearse all seven Christmas groups, including phone voting 1–7, leave competition and return to standard slides. Verify all scores and CSV, and refresh all devices after deployment.

No Cloudflare binding, Worker name or admin secret changes. The prior 12 MB total design payload cap and other V3.0 limitations still apply. Keep previous backup: a code-only downgrade after saving inherited slides is not a safe data rollback.
