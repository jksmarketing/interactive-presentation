# V3.0.3 — Independent participant screens

Base: complete V3.0.2 archive. This is a targeted extension, not a new application. Existing storage binding, migration tag, routes and Worker name remain unchanged.

## Changes
- Each slide stores optional `phoneMode`, `phoneHeadline`, `phoneMessage`, independently of its TV type, title and subtitle. Older slides default to automatic; existing waiting copy and competition behavior remain. Automatic QR slides now share the real room-specific join QR and URL on phones. Share uses the existing local QR generator and native Web Share or clipboard when available; a visible URL is always provided.
- The editor's Phone → Content panel exposes all five modes and optional copy. Preview selection supports configured idle screen and active phases on interactive slides. Existing mobile backgrounds, logo, theme and fonts are reused.
- The live controller can select which TV's slide the idle phone follows. Active competition/interactive responses always take priority, even when a different idle mode or TV source is selected.
- Persistent `phoneEnded` and `phoneSource` state is authenticated, saved with the room and distributed through the existing public state mechanism. Finishing is rejected during a running/paused countdown or open vote/activity. Reopen or a deliberate new start clears the persistent end flag. A new presentation or rehearsal copy resets live flags but preserves slide settings. No automatic inference of the final game is attempted.
- The original active-round editing restriction is unchanged. No R2 migration or unrelated editor/controller redesign is included.

These are Node backend simulations and VM-based static markup/handler tests, not real browser tests. Native sharing, visual layout, QR scanability from a physical phone, and actual Cloudflare deployment have not been verified in this turn.

## Acceptance on staging or rehearsal copy
1. Select a standard TV slide. In Phone → Content select Waiting screen and enter custom headline and message. Save, display the slide and compare phone preview to actual `/join`.
2. Show a Join session slide with Automatic mode; confirm the phone has a scannable QR for the correct presentation, including its `p` identifier when applicable. Try sharing/copying the link. Verify the TV remains unchanged when switching phone mode to Custom information.
3. With different TV slides, toggle the idle phone source; verify the appropriate mobile design and message. Start a competition on either TV while an idle Finished mode is selected: phone must show the countdown and then 1–7 voting. Finish the round and verify the configured idle mode returns.
4. Verify the Finish games button is rejected during an active round. After the last game ends, click it, confirm, navigate to other TV slides, reload the controller and open a fresh `/join` tab. Both existing and new guests should see the closing screen. Reopen games and ensure the configured mode resumes. Deliberately starting a new round also clears the end flag.
5. Test in light/dark editor themes, a real iPhone/Android, and your actual two TVs. Check long text and QR fit on the phone. Confirm a rehearsal copy has independent live state.
