# JKS Interactive V3.0.6 — targeted UX audit

Base: exact V3.0.5 ZIP. Frontend and Worker changes. Cloudflare settings unchanged.

## Participant flow
- Reserved header, card and footer rows remove the overlap between presentation name/logo and content. Mobile logo movement is still available, but vertical position is constrained to the safe header; unusually tall custom text or many poll options may require vertical scrolling. Existing slide art is not altered.
- QR share screen uses shorter generic text, a scannable QR with quiet zone, and a short link label instead of displaying the entire URL. The actual target remains the current presentation's join URL.
- Competition and standalone rating screens use compact multi-column number grids, 44px targets on the live phone, explicit selection then confirmation. Polls retain one-tap submission. Word cloud uses a 40-character single-line input, Q&A a 300-character multi-line input, with character counts and appropriate labels. Text submit enables only when nonblank and online. Inputs use a desaturated color sampled from the uploaded background image, with a configured background-color fallback and a contrasting text color. Explicit voting card color remains configurable.
- Video automatic mode shows an instruction to look at the screen, in both preview and live view; custom phone screen mode still overrides idle automatic content. Active interactions take precedence. Waiting and closing default wording is event/time-neutral; existing user-authored text stays unchanged.
- Shared renderer used by editor, live preview and participant screen. No change to original networking architecture, session links or vote receipt validation.

## Competition flow
- Independent per-slide group rosters, duration and rating scale; legacy group list is copied on first roster edit. New competitions start with a copy, not a shared reference. Existing ledgers and scores are retained.
- Admin-only all-competitions summary with counts, scores and per-competition CSV. Current on-air competition is explicit, with slide numbers in selectors. Start/close/reset confirmations identify the contest. One audience activity can accept responses at a time, by design.
- Each results slide has its own explicit source and published snapshot; two TVs can show different results slides simultaneously. Unlinked results with multiple competitions require a source selection. A single competition is preselected when unambiguous. Reset/redo invalidates results for that contest only; score changes do not overwrite the other contest. Existing single-contest legacy publication is migrated when unambiguous; old ambiguous multi-contest publication must be republished explicitly. No private score overview is sent to public clients. Duplication/import remaps result source IDs and starts with empty scores.
- Editing or deleting scored group IDs is protected until that competition is reset. The existing restriction on saves during any active interaction remains; close the round before editing. This release does not change that restriction or add server version history.

## Verification performed
- `npm test`: all ten Node suites (syntax, library, navigation, upgrade, activities, migration/concurrent votes, static rendering, participant, theme, phone modes, new multi-competition suite; syntax is a separate check). Tests use simulated Worker storage, not the deployed Cloudflare service.
- `npm run test:browser`: real Chromium DOM and CSS, using an isolated HTML document and the actual application code with fake location and mocked API. 36 layout states at 320×568, 390×844, 430×932; header/card/footer non-overlap and no horizontal overflow; QR size; 10-point rating click and explicit submit; word cloud/Q&A entry, count and send; actual result-source dropdown, publish dialog, private scores, editor independent roster changes and result linking. Also tested a phone-sized preview. No live network, physical QR scan, native sharing or actual TV synchronization in this harness.
- New Worker tests verify separate rosters and scales even with identical group IDs, rejected stale start, separate publications, explicit source selection, public privacy, persisted reload, scoped reset and import/copy references.

## Before production
1. Export the current presentation and keep the V3.0.5 release. Deploy the new code to staging/rehearsal before production. A design export excludes votes; a code rollback does not restore database state.
2. Open the actual join page on iOS and Android, scan the QR from a TV, share the link, and check each activity using your actual mobile artwork and logos.
3. Create two competitions with different groups; run a short round in each, switch between them, confirm scores stay independent, and publish each linked results slide. Test both TVs, the existing navigation override and reconnect behavior.
4. Test the final event workflow with the real network and devices. No production-readiness guarantee until these pass.
